# PetShelf 组件架构

本文档把 PetShelf 拆分为可复用 UI、产品界面、数据适配层和资源需求。新增或调整页面组件时，应结合 `docs/设计系统.md` 一起使用。

## 当前项目情况

当前技术栈：

- React + Vite
- 原生 CSS，位于 `src/styles/`
- 静态演示数据，位于 `src/data/pets.js`
- 浏览器端上传校验，位于 `src/utils/uploadValidation.js`

当前界面：

- 首页资源网格：`src/pages/HomePage.jsx`
- 宠物详情页原型：`src/pages/PetDetailPage.jsx`
- 顶部栏：`src/components/AppHeader.jsx`
- 宠物卡片：`src/components/PetCard.jsx`
- 用户面板：`src/components/UserPanel.jsx`
- 上传弹窗：`src/components/UploadDialog.jsx`
- 上传弹窗子组件：`src/components/upload/`

近期架构目标：

- 继续让 `App.jsx` 只保留全局状态、hash 详情选择和页面组合。
- 将详情页内部的元信息、预览区、状态条和包结构逐步拆成可复用组件。
- 将通用控件与具体业务界面继续分离。
- 在接入真实 spritesheet 前，先固化详情页数据契约和预览组件边界。

## 页面级组件

### `AppShell`

职责：

- 共享页面框架。
- 顶部栏。
- 页脚。
- 如果上传仍是全局能力，则由它持有上传弹窗入口。

常见 props：

- `children`
- `query`
- `onQueryChange`
- `onUploadSelect`
- `userPanelState`

注意：

- 外壳视觉规则必须遵循 `docs/设计系统.md`。
- 首页不增加全局左侧边栏。

### `HomePage`

职责：

- 搜索过滤。
- 排序状态。
- 资源数量。
- 空状态。
- 宠物网格组合。
- 在有选中宠物时切换到详情页。

子组件：

- `SortControls`
- `PetGrid`
- `PetCard`
- `EmptyState`
- `PetDetailPage`

状态：

- 默认资源网格。
- 搜索无结果。
- 全站没有宠物。
- 选中宠物详情。
- 后续接入后端后的加载状态。

### `PetDetailPage`

职责：

- 展示单个宠物的元数据和预览状态。
- 提供下载与点赞动作。
- 展示兼容性和包结构信息。
- 当前阶段使用 `PixelPet` 作为真实 spritesheet 接入前的占位预览。
- 可通过 `/#pet={id}` 直达。

子组件：

- `PetDetailHero`
- `PetMetaList`
- `PetPreviewStage`
- `PetStateStrip`
- `PetActionBar`
- `PetCompatibilityPanel`

状态：

- 宠物加载中。
- 宠物不存在。
- 预览资源不可用。
- 下载处理中。
- 点赞处理中。
- 点赞失败。

## 详情页组件拆分

参考图提供的是“两栏检查面板”：左侧信息，右侧大预览，预览下方是状态缩略图条。PetShelf 可以保留这个结构，但要适配资源库应用的克制界面。

### `PetDetailHero`

职责：

- 组合详情页主体检查界面。

桌面布局：

- 左列：`PetMetaPanel`
- 右列：`PetPreviewPanel`

移动端布局：

- 预览面板优先。
- 元信息面板在后。
- 如果下载成为核心转化动作，后续可考虑底部粘性操作条。

### `PetMetaPanel`

字段：

- 展示名
- Manifest ID
- 作者
- 描述
- 下载量
- 点赞量
- 后续上传时间
- 包兼容性

动作：

- `下载`
- `喜欢`
- `复制 ID`

实现建议：

- 元数据使用定义列表结构。
- 图标只在提升扫读效率时使用。
- 描述可读即可，不要做成大段营销文案。

### `PetPreviewPanel`

字段：

- 当前动画状态。
- 大预览区域。
- 状态选择器。
- 后续播放控制。

实现建议：

- 有真实 spritesheet 时，大预览应读取真实帧。
- 演示数据缺少真实 spritesheet 时，使用 `PixelPet` 临时占位。
- 预览面板可以使用柔和表面，但不要变成卡片套卡片。

### `PetStateStrip`

状态来自 atlas 契约：

- `idle`
- `running-right`
- `running-left`
- `waving`
- `jumping`
- `failed`
- `waiting`
- `running`
- `review`

展示标签：

- `站立`
- `向右跑`
- `向左跑`
- `挥手`
- `跳跃`
- `失败`
- `等待`
- `跑步`
- `检查`

实现建议：

- 状态条应使用 tablist 或分段选择语义。
- 每个状态需要从该状态第一帧生成缩略图。
- 当前状态必须支持键盘访问，并有明确视觉选中态。

### `PetCompatibilityPanel`

字段：

- Atlas 尺寸：`1536x1872`
- 网格：`8x9`
- 单格：`192x208`
- 必填 manifest 字段
- 图片格式：PNG 或 WebP

用途：

- 详情页。
- 后续上传成功预览。
- 后续文档示例。

## 通用组件

### `ActionButton`

变体：

- `primary`
- `secondary`
- `ghost`
- 后续 `danger`

要求：

- 通过可见文本或 `aria-label` 提供可访问名称。
- 支持加载和禁用状态。
- 支持图标前缀。

### `IconButton`

使用场景：

- 关闭
- 通知
- 卡片快捷操作
- 轮播箭头

要求：

- 必须传入 `aria-label`。
- 焦点状态可见。
- 有实际意义的操作不能只在鼠标悬停时可用。

### `StatItem`

使用场景：

- 下载量
- 点赞量
- 文件数量
- 包大小

字段：

- `icon`
- `label`
- `value`

### `Tabs`

使用场景：

- 用户面板标签页。
- 宠物状态选择。

规则：

- 切换内容面板时使用真实 tab 语义。
- 只改变预览状态时，可使用 `aria-pressed`。

## 上传组件拆分

当前 `UploadDialog.jsx` 后续可拆成：

- `UploadDialog`
- `UploadChecklist`
- `UploadPetInfo`
- `UploadPreview`

当前 `src/utils/uploadValidation.js` 继续保留在 UI 外部，负责浏览器端校验。

目前拆分状态：

- `UploadDialog` 负责弹窗壳、上传状态映射和确认动作。
- `UploadChecklist` 负责读取、校验、预览生成三步进度。
- `UploadPetInfo` 负责校验成功后的宠物信息摘要。
- `UploadPreview` 负责上传预览、状态切换和帧播放。

后续上传状态：

- `idle`
- `selecting`
- `validating`
- `failed`
- `preview`
- `confirming`
- `completed`

## 数据适配计划

当前 `src/data/pets.js` 可以继续作为演示数据，但应逐步对齐后端字段：

```js
{
  id,
  manifestId,
  displayName,
  description,
  author,
  downloads,
  likes,
  spritesheetPath,
  previewState,
  createdAt,
  atlas
}
```

引入后端前可先增加适配帮助函数：

- `getPetById(pets, id)`
- `sortPets(pets, sort)`
- `searchPets(pets, query)`
- `getPetPreviewFrame(pet, state)`

显示格式化继续放在 `src/utils/format.js`。

## 资源与非代码需求

目标设计中有些部分无法只靠布局代码完成。

### 真实宠物资源

需要：

- 符合 Codex Pet Contract 的真实宠物文件夹。
- `pet.json`
- `spritesheet.webp` 或 `spritesheet.png`
- 透明背景。
- 正确 atlas 尺寸：`1536x1872`。

原因：

- 详情页大预览和状态缩略图需要真实帧。
- 参考图中的预览质量依赖真实角色素材。

临时方案：

- 使用 `PixelPet` 占位。
- 在实现说明中标记为临时占位，不必在用户界面中过度解释。

### 状态缩略图

需要：

- 客户端从 `spritesheet` 和 atlas 元数据生成缩略图；或
- 上传后预生成缩略图并存储。

建议：

- MVP 阶段可以客户端生成。
- 生产阶段建议存储生成后的预览图，以提升网格和详情页性能。

### 动画预览

需要：

- 每个状态的帧时序。
- 能推进 atlas 单元格的渲染器。

可通过代码实现：

- Canvas 渲染器。
- CSS sprite `background-position` 动画。

需要产品决策：

- 详情页预览是否自动播放。
- 状态选择是否立即切换动画。
- 开启减少动态效果的用户是否只显示静态帧。

### 下载包

需要：

- 存储原始上传文件夹。
- 下载时由服务端或客户端组装归档。

无法仅靠前端完成：

- 持久化存储。
- 有身份的归属关系。
- 不易被刷的下载计数。

### 点赞

需要：

- 用户身份。
- 宠物与用户的点赞关系表。
- 乐观更新和服务端回写。

无法仅靠前端完成：

- 跨设备持久点赞状态。
- 抗滥用点赞计数。

### 参考图级别美术素材

参考图使用高质量角色多姿态素材。PetShelf 需要来自创作者或生成流程的等价资源：

- 站立姿态。
- 跑步姿态。
- 挥手、跳跃、失败、等待、检查姿态。
- 干净透明背景。
- 各帧比例一致。

如需生成素材，生成说明必须包含 `docs/宠物数据模型.md` 中的 atlas 契约和行状态布局。

## 推荐实现顺序

1. 已完成：从 `App.jsx` 拆出 `HomePage`、`PetGrid`、`SortControls`。
2. 已完成：补齐排序入口：`最多下载`、`最多喜欢`。
3. 已完成：让卡片主区域支持进入详情，并保留下载、喜欢快捷操作。
4. 已完成：拆分上传弹窗子组件。
5. 已完成：增加详情页数据形态，并用现有演示宠物做静态详情页原型。
6. 下一步：将 `PetDetailPage` 内部继续拆出 `PetPreviewStage`、`PetStateStrip`、`PetCompatibilityPanel`。
7. 获取真实宠物素材后，再加入 spritesheet 缩略图生成和详情页动画预览。

在详情页仍处于静态原型阶段时，不急着引入复杂路由；当前 hash 导航足够支撑演示和直达。
