# PetShelf 设计系统

本文档定义 PetShelf 的统一 UI/UX 规范。新增页面和组件时，应优先复用本文档中的视觉方向、设计令牌、组件规则、状态规范和可访问性要求。若新需求不适配当前设计系统，应先更新设计系统，再实现界面。

## 设计原则

- PetShelf 是宠物资源库应用，不是营销落地页。
- 首屏应直接呈现工作界面：搜索、排序、上传、用户入口和宠物资源。
- 整体气质保持轻、干净、实用，通过像素宠物资源建立温暖记忆点。
- 优先使用间距、对齐、层级、文字和状态表达，不依赖装饰。
- 卡片只用于资源对象、弹窗、浮层和重复交互项，避免嵌套卡片和装饰型区块卡片。
- 宠物资源本身应是最强视觉信号，界面框架保持安静。

## 产品界面模型

主要工作区：

- 顶部栏：品牌、搜索、上传、文档、通知、用户入口。
- 主内容：页面标题、资源数量、排序控件、宠物网格。
- 上传弹窗：本地校验、预览、确认。
- 用户面板：`我的上传`、`我的点赞`。

次级界面：

- 文档页后续可以拥有自己的文档导航。
- 详情页聚焦宠物预览、包元数据、下载动作、作者信息和兼容性说明。
- 账户页仅在用户面板无法承载管理动作时再扩展。

## 视觉方向

视觉命题：

PetShelf 是一个明亮的像素宠物陈列架：白色工作台、柔和蓝灰结构、单一薄荷青强调色，以及作为记忆点的宠物像素素材。

关键词：

- 克制
- 清爽
- 资源导向
- 友好，但不牺牲可读性

避免：

- 在应用页面加入大型营销 Hero
- 装饰性渐变光斑
- 仪表盘式卡片矩阵
- MVP 阶段使用重度暗色主题
- 多个互相竞争的强调色

## 设计令牌

### 颜色

`src/styles/global.css` 中的 CSS 变量是颜色令牌的代码来源。

| 令牌 | 当前值 | 用途 |
| --- | --- | --- |
| `--bg` | `#ffffff` | 页面背景 |
| `--surface` | `#ffffff` | 卡片、弹窗、面板 |
| `--surface-soft` | `#f8fbfb` | 搜索框、柔和控件背景 |
| `--surface-mint` | `#eefbf7` | 柔和选中态、详情信息面板或管理动作背景 |
| `--surface-mint-strong` | `#d8f5eb` | 薄荷绿组件中的强化层级 |
| `--preview-bg` | `#ffffff` | 宠物动画预览画布底色 |
| `--preview-bg-soft` | `#fbfdfe` | 宠物动画预览画布柔和底色 |
| `--preview-grid` | `rgba(203, 213, 225, 0.34)` | 宠物预览浅灰蓝细网格线 |
| `--preview-glass` | `rgba(255, 255, 255, 0.78)` | 预览工具栏和半透明面板 |
| `--text` | `#17212b` | 主文本 |
| `--muted` | `#64748b` | 次级文本 |
| `--border` | `#e2eaf0` | 分割线和轻边框 |
| `--accent` | `#0a9b86` | 主操作和选中态 |
| `--accent-dark` | `#087a6d` | 悬停和强调操作 |
| `--accent-soft` | `#dcf7ef` | 柔和成功态或选中背景 |
| `--active-accent` | `#0f8f7e` | 动画状态条中当前状态的品牌青绿强调 |

状态色：

- 成功：使用 `--accent` 或 `--accent-soft`。
- 错误：文本使用克制红色，如 `#c0392b`；背景可使用 `#fff8f7`。
- 禁用：使用蓝灰表面和弱化文本，避免低对比灰上灰。

规则：

- 产品 UI 只保留一个强调色体系。
- 宠物素材本身可以有不同颜色，但控件不要跟随每只宠物变色。
- 新增全局颜色时，必须同步更新本文档和 `global.css`。

### 字体

字体栈：

```css
Inter, "PingFang SC", "Microsoft YaHei", system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
```

| 角色 | 字号 | 字重 | 说明 |
| --- | ---: | ---: | --- |
| 页面标题 | 28-32px | 700-800 | 如 `宠物` |
| 弹窗标题 | 20-24px | 700-800 | 优先单行 |
| 卡片标题 | 15-17px | 700-800 | 资源名称 |
| 正文 | 14-15px | 400-500 | 元数据和描述 |
| 工具标签 | 12-13px | 700-800 | 标签、状态、小型信息 |
| 按钮 | 14-15px | 700 | 避免尴尬换行 |

规则：

- 字距保持 `0`。
- 不使用视口宽度动态缩放字体。
- 应用界面使用功能性文案，避免营销式口号。

### 间距

基础间距使用 8px 节奏：

| 名称 | 值 |
| --- | ---: |
| `space-1` | 4px |
| `space-2` | 8px |
| `space-3` | 12px |
| `space-4` | 16px |
| `space-5` | 20px |
| `space-6` | 24px |
| `space-8` | 32px |
| `space-10` | 40px |
| `space-12` | 48px |

规则：

- 优先使用 8px 倍数。
- 区块之间的间距大于组件内部间距。
- 允许信息密度较高，但标签、对齐和状态必须清晰。

### 圆角

| 元素 | 圆角 |
| --- | ---: |
| 标准按钮和输入框 | 8px |
| 资源卡片 | 8-10px |
| 面板内标签页 | 7-9px |
| 弹窗和浮层 | 12-14px |
| 圆形头像和徽章 | 999px |

规则：

- 默认使用 8px。
- 除非表达选中或紧凑分组，不使用过度胶囊化的形状。

### 阴影

仅在这些场景使用阴影：

- 用户浮层
- 弹窗
- 卡片悬停态
- 卡片快捷操作浮层

常规页面区块不要使用阴影。

## 布局规则

顶部栏：

- 保留当前结构：品牌、搜索、文档、上传、通知、用户头像。
- 搜索是核心操作，不是次级细节。
- 上传是主要行动按钮。

首页：

- 首页直接呈现资源网格。
- 不增加全局左侧边栏。
- 排序控件靠近页面标题和资源数量。
- 页面内容应有最大宽度约束，但外壳保持全宽。

移动端：

- 顶部栏要可预测地折叠。
- 不允许横向溢出。
- 上传、搜索、用户入口应保持可达。
- 按钮和紧凑面板中的文字不能尴尬换行。

## 组件规范

### 按钮

按钮类型：

- 主按钮：上传、确认。
- 次按钮：取消、清空、低风险操作。
- 图标按钮：通知、关闭、卡片快捷操作。
- 小按钮：紧凑管理动作。

规则：

- 标准动作使用 `lucide-react` 图标。
- 纯图标按钮必须有 `aria-label`。
- 主按钮要清晰，但不要过大。
- 禁用态需要通过邻近文案解释，不只依赖颜色。

### 搜索

- 占位文案说明可搜索字段。
- 搜索无结果时显示查询词，并提供清空动作。
- 键盘焦点必须可见。

### 排序控件

支持排序：

- `热门`
- `最新`
- `最多下载`
- `最多喜欢`

规则：

- 使用紧凑按钮组或分段控件。
- 当前选中态必须清晰，并通过 `aria-pressed` 或等效状态表达。

### 宠物卡片

必备字段：

- 宠物预览
- 名称
- 作者
- 下载量
- 点赞量

规则：

- 卡片代表一个宠物资源，因此允许使用卡片样式。
- 悬停可轻微上浮并展示快捷操作。
- 快捷操作必须支持键盘访问。
- 当前像素占位图只是临时方案，后续应替换为真实 spritesheet 渲染。

### 宠物详情页

主要任务：

- 帮助用户检查单个宠物、预览状态、点赞并下载。

推荐结构：

- 使用与首页一致的顶部栏。
- 桌面端主体为两栏：
  - 左侧：宠物名、manifest ID、展示名、作者、描述、统计、兼容性和主要操作。
  - 右侧：大预览区域、状态选择器、缩略图条和后续播放控制。
- 移动端改为单列：
  - 如果用户从卡片进入，预览优先。
  - 元信息和操作放在预览之后。

规则：

- 详情页可以使用比首页更聚焦的大型展示面，因为此时宠物本身是被检查对象。
- 参考图的“两栏信息 + 大预览 + 状态条”可以保留，整体应像嵌入式薄荷绿弹窗：左侧信息清晰分组，右侧预览使用白色画布、低对比浅灰蓝细网格、玻璃感状态条和轻阴影；薄荷绿只用于操作与层级强调。
- 操作文案保持功能性：`下载`、`喜欢`、`复制 ID`、`查看规范`。
- 状态名称来自宠物 atlas 契约，不随意创造营销标签。
- 没有真实 spritesheet 时，使用明确的临时占位方案，并在实现文档中说明缺失资源。

### 上传弹窗

状态：

- 校验中
- 校验失败
- 预览就绪
- 已确认或已完成，等持久化能力加入后补充

规则：

- 用户可见校验摘要保持紧凑，只显示 `文件夹大小`、`pet.json`、`spritesheet`。
- 成功后隐藏校验细节，只展示宠物信息。
- 校验失败时禁用确认。
- 弹窗应支持关闭按钮、`Esc` 和焦点恢复。
- 后端接入后必须重复服务端校验。

### 用户面板

内容：

- 用户身份
- 管理入口
- `我的上传`
- `我的点赞`

规则：

- 在内容变复杂前，保持轻量浮层。
- 每个标签页都需要空状态。
- 管理动作应紧凑直接。

### 空状态

需要覆盖：

- 全站没有宠物
- 搜索无结果
- 我的上传为空
- 我的点赞为空
- 上传失败

规则：

- 空状态说明范围和下一步动作。
- 避免长篇教学文案。
- 可以使用小型像素宠物视觉辅助。

## 交互与动效

用动效强化层级，而不是制造噪音：

- 卡片悬停：轻微上浮和快捷操作显现。
- 面板/弹窗：短促透明度和位移动效。
- 上传校验：明确表现校验中、失败、预览就绪之间的变化。

规则：

- 动效快速、克制。
- 避免让资源浏览界面显得不稳定。
- 添加大范围动效时需要尊重 `prefers-reduced-motion`。

## 可访问性

基线要求：

- 操作用 `button`，导航用 `a`。
- 所有纯图标操作必须有可访问名称。
- 焦点状态必须可见。
- 弹窗后续应完整管理焦点。
- 弹窗关闭应支持 `Esc`。
- 校验状态不能只依赖颜色。
- 文本和控件需要保持可读对比度。

键盘预期：

- 搜索框可正常聚焦。
- 排序控件可达，并能表达选中状态。
- 卡片快捷操作不依赖鼠标悬停。
- 用户面板标签页使用一致的按钮或 tab 语义。

## 实现流程

创建或修改 UI 时：

1. 先检查本文档。
2. 复用现有令牌、组件模式和布局规则。
3. 如果需求需要新增令牌、组件变体或交互规则，先更新本文档和 `src/styles/global.css`，再实现界面。
4. 改动范围应限制在相关产品界面内。
5. 有意义的前端改动提交前运行 `npm run build`。

验收清单：

- 使用了现有设计令牌，或已记录新增令牌。
- 适用场景包含空、加载、错误状态。
- 移动端无横向溢出。
- 交互元素具备键盘访问和可访问名称。
- 文案是产品界面文案，不是营销填充。
- 没有引入嵌套卡片或装饰性区块卡片。
