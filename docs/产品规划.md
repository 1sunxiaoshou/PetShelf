# PetShelf 产品设计与规划

> 2026-09-03：项目收尾为静态展示 Demo。当前保留浏览、搜索、排序、本机收藏、详情动作、V1/V2 兼容预览、本地文件夹检查和静态下载；不做登录、服务端上传或数据库依赖。下文记录历史产品设想，当前实现以根目录 README 和 Demo 说明页为准。

本文档用于记录已经确认的设计决策和后续待讨论范围，避免实现过程中漂移。

## 产品定位

PetShelf 是一个面向 Codex 宠物系统的轻量、简洁桌宠资源库网页。第一阶段重点是浏览、搜索、排序、上传宠物文件夹、个人面板管理自己的上传和点赞。

## 已确认决策

- 首页去除左侧边栏，改为顶部导航 + 主内容网格。
- “我的上传”和“我的点赞”放进右上角轻量用户面板，不作为首页侧边导航。
- 上传按钮保持当前主按钮样式，文案为：`上传`。
- 首页卡片继续使用现有字段：宠物图、名称、作者、下载量、点赞量。
- 排序使用圆角按钮，不使用复杂筛选字段。
- 暂不做审核流。
- 详情页先以静态原型推进，使用现有演示数据展示元信息、预览区、状态选择和包结构。
- 当前阶段不引入复杂路由，宠物详情使用 hash 直达，例如 `/#pet=1`。
- 帮助与规范统一为文档界面，内部再区分各自文档。
- 宠物包规范以 `hatch-pet` 的 Codex Pet Contract 为准，详见 `docs/宠物数据模型.md`。

## 首页规划

首页路径：`/`

首屏组成：

- 顶部品牌：PetShelf。
- 搜索框：支持按宠物名称、作者搜索。
- 上传按钮：点击后打开文件夹选择，选择宠物文件夹后进入上传流程。
- 通知图标：暂作为轻量入口占位。
- 用户头像：点击打开用户面板。
- 主标题：宠物。
- 资源总数。
- 排序按钮：热门、最新、最多下载、最多喜欢。
- 宠物卡片网格。
- 空状态：搜索无结果或无资源时展示。

首页宠物卡片主区域进入详情；下载和喜欢保留为独立快捷操作。

## 详情页规划

当前详情页为前端静态原型，用于验证信息结构和视觉布局。进入方式：

- 从首页宠物卡片进入。
- 通过 hash 直达，例如 `/#pet=1`。

当前内容：

- 返回宠物列表。
- 宠物名称、描述、作者、Manifest ID。
- 下载和喜欢操作入口。
- 基于本地测试 spritesheet 的真实帧预览。
- 基于 atlas 契约的动画状态选择和缩略图条。
- 包结构信息：Atlas 尺寸、网格、单格、spritesheet 路径。

当前测试资源来自本地 Codex 宠物目录，复制到 `public/pets/atri/` 作为唯一静态测试数据；前端列表不再生成额外虚假宠物。后续接入真实资源库后，详情页应从宠物记录的 spritesheet 路径生成同样的 `previewFrames`。

## 上传流程规划

流程：

1. 点击 `上传`。
2. 打开系统文件夹选择框。
3. 选择宠物文件夹后进入上传。
4. 自动校验文件结构。
5. 解析并渲染预览弹窗。
6. 用户手动确认。
7. 完成上传。

第一版前端先完成本地文件夹解析和校验；接入后端后，校验、解析和存储放到服务端。

上传文件夹的目标结构来自 `hatch-pet`：

```text
pet.json
spritesheet.webp
```

核心校验包括文件夹总大小小于 `10MB`、`pet.json` 必填字段、spritesheet 文件存在、atlas 尺寸 `1536x1872`、8 列 9 行、单格 `192x208`、透明背景。弹窗只展示 3 条用户可理解的摘要校验：文件夹大小、`pet.json`、`spritesheet`。

PetShelf 不接收 Zip。服务端按原始文件夹结构存储文件；用户下载时再由客户端或本地工具按需组装。

## 用户面板规划

右上角头像点击展开轻量面板：

- 用户头像、昵称、个人主页路径。
- 管理信息入口。
- `我的上传` tab。
- `我的点赞` tab。
- 我的上传内可以管理自己的作品。

后续如果面板内容过多，再扩展成 `/me` 页面。

## 空状态规划

需要覆盖：

- 全站还没有宠物：展示轻量像素宠物占位和上传引导。
- 搜索无结果：展示搜索词和清空搜索按钮。
- 我的上传为空：提示还没有上传，并提供上传入口。
- 我的点赞为空：提示还没有点赞，并引导继续浏览。
- 上传失败：在上传弹窗内展示失败原因和重新选择。

## 文档中心规划

后续路径：`/docs`

文档中心包括：

- 上传规范。
- 宠物文件夹结构。
- 宠物配置文件说明。
- 安装和使用说明。
- 常见问题。

文档页可以有自己的左侧目录，但首页不保留全局侧边栏。

## 技术架构建议

第一阶段：

- 前端：React + Vite。
- 样式：CSS/Tailwind 二选一，当前原型先用原生 CSS 保持轻量。
- 部署：Vercel、Netlify 或 Cloudflare Pages。
- 数据、登录、文件：后续接 Supabase Auth + Postgres + Storage。

后续接入服务端时需要补充：

- 宠物表。
- 用户表或 Supabase Auth 用户元信息。
- 点赞关系表。
- 上传文件存储桶。
- 服务端文件夹结构校验和 manifest 解析。
- atlas 几何校验和上传任务校验报告。
